# 应用提交审查验收

日期：2026-10-17。该记录验证流程、身份绑定和已知失败回归，不代表企业用户验收、全面静态分析能力或回答准确率。

## 验证内容

- 默认登记应用在真实仓库 `HEAD` 可收集 12 个文件，包含调用层、归一化、适配器、未修改的消费者、输出契约、设计与测试。读取的是 Git 对象，工作区未提交改动不会被采用。
- 使用已有原创“旧结果消费”和“字段适配”变体建立本地 Git 演示提交，明确标为学生演示历史，不作为企业内部发行历史。候选只修改归一化文件，两边均审查完整登记上下文。原先 1 项旧索引风险在候选中未观察到；因仍有资料/分析缺口，对照保持 `UNRESOLVED`，没有认证修复完成。
- 真正登记的原始应用提交经过知识服务和 Agent 完整预审，取得 5 条应用契约/测试资料证据，最终为 `needs_verification`。包含适配器和跨函数实参关系时，当前工具仍可能无法定位旧结果风险，不能用“收集完整”代替“分析充分”。
- 应用证据再次核对提交、路径、行号、文本和哈希。错误提交的证据拒绝关联；官方组件证据与应用契约证据保持分开。
- 外部回归记录必须匹配应用 ID、应用提交、报告、文件哈希、目标依赖和环境。缺必需角色时，即使人工填写接受残余风险，也不能关闭输入完整性阻断。
- 任务结果重开数据库可取回，错误令牌与变更后的输入身份拒绝恢复；不同工作进程遗留任务标为中断。已完成查证响应可跨重启显式复用，失败调用不缓存。没有自动模型重跑或代码执行。
