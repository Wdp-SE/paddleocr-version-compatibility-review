# PaddleOCR 当前 RAG 验证记录

本轮保留文档处理应用的依赖升级业务和官方中文知识空间（58 来源、1754 原文块），优化统一 RAG，供开发者查询与受控 Agent 查证使用。没有更换语料，也没有把检索候选升级为已确认的兼容性结论。

## 当前结果

统一版本范围、Top-5 和 40 候选窗口。12 条开发题用于选型；8 条按文档产线分组的留出题没有参与策略调整。标签由开发者依据原文编写，不是独立专家盲评。

| 配置 | 开发题完整事实覆盖 | 开发题非目标模块片段 | 留出题完整事实覆盖 | 留出题非目标模块片段 |
|---|---:|---:|---:|---:|
| 原始块 BM25 | 9/12 | 31 | 5/8 | 26 |
| 产线范围 + 窗口 BM25 | 10/12 | 8 | 7/8 | 0 |
| 范围 + MiniLM 重排 | 10/12 | 2 | 未测 | 未测 |
| 范围 + 中文 BGE 重排 | 11/12 | 6 | 未测 | 未测 |
| 范围 + 语义/关键词 RRF + BGE | 10/12 | 4 | 未测 | 未测 |
| 范围 + 受约束模型重排 | 11/12 | 5 | 7/8 | 0 |

全部已执行配置的错版片段数为 0，但这组问题均明确指定 v3.0.0，不能据此宣称所有跨版本问题都正确。神经模型采用自身 tokenizer 构建窗口，因此整套配置比较不是只更换 ranker 的单变量消融。BM25 和模型重排共享同一窗口表示。

“非目标模块”按预定模块分类统计，通用迁移指南也可能计入；它不等于每个被计数片段都语义无关或错误。

按开发集的完整覆盖、再按非目标模块片段数，暂选 `contextual_llm_rerank`。留出与范围 BM25 持平，没有证明重排在新产线上普遍更好。排序结果可能波动，不能把 11/12 描述为生产回答准确率或统计显著优势。保留 BM25 对照与明确的模型不可用回退。

`selection.json` 在留出执行前保存；额外的保守发布规则在打开完整留出结果前记录，但当时报告文件已生成。这不是一个预注册的科学实验。没有根据留出结果改参数、改标签或再次跑留出。原始事实覆盖和为生成补齐的上下文覆盖分开记录，本轮两者数值相同。

## 为什么这样改

- 文档中的同名字段属于不同产线。先确定用户指定的版本与产线，再截取候选，避免表格、版面解析和 OCR 的 `rec_texts` 互相挤占。
- HTML 参数表和代码样例容易被切开。检索使用短窗口，生成和核验从同一原文块补齐表头、表格行和代码围栏；窗口身份与偏移必须匹配原文。
- 模型重排只能重新排列既有窗口 ID，不能创造证据；不把排序分数解释成答案正确概率。比较包括中文 BGE、MiniLM 和融合召回，最终没有因为 RRF 更复杂而采用它。
- 生成先检查引用身份、版本和模块，再核对可机械检查的默认值与原文支持。内容不通过时最多补查一次，保留已核验主张和具体缺口；模型或核验服务故障不触发这次付费重生成。

## 真实调用探针

使用 `deepseek-flash` 跑了 5 个实际调用：逐个保存 JSON、解释过滤后的识别字段、结构接口迁移、CPU 默认值、无依据的 100% 准确率保证。前四项返回通过模型核验的主张；最后一项明确限定为“检索证据没有这种保证”，没有承诺任意图片准确率。正例的关键事实可在保存的固定原文中检查，`predict` 返回 list 还可在官方 `paddleocr/_pipelines/ocr.py` 查到。

5 次探针用时 17.6–40.5 秒，供应商报告的重排、生成、核验用量合计 67119 Token，1 次补查。它们只证明这次链路可运行并提供可审计输出，不是回答准确率、P95、零幻觉或独立人工验收。生成和核验采用同一模型，可能共享偏差；负例回答还有重复措辞，输出可读性仍有改善空间。

## 保留的失败项

- 开发题 `v4-03`：自然语言询问逐个打印并保存图片，Top-5 没有完整包含所需代码事实。
- 留出题 `v4-14`：文档预处理的所有角度分类值，没有完整覆盖标注事实。

没有针对这两条写题目专用召回规则。后续需要独立人员编写更多不同措辞、跨版本、不可回答和真实应用问题，再判断收益是否稳定。不要继续用本组留出题选参数。

模型重排每轮最多处理 40 个窗口。补查虽扩大检索池到 120 并增加最终原文数，但当前模型重排仍只处理前 40 个，不代表已充分利用整个扩大池；不能将它宣传为无限多轮查证或保证召回遗漏都被修复。

## 发布与复现

`final/release-lock.json` 绑定代码、语料注册表、原文件和实验产物；加载时逐文件核对哈希、重建原文证据并重算指标。任一内容漂移后不继续展示旧成绩。`auto` 仅在发布结果有效时使用选中的策略。Agent 共用这一检索入口，其静态发现与人工确认边界保持不变；本轮没有测出新的 Agent 端到端成功率。

`final/` 是当前实现的结果，根目录、`scope-corrected/` 和 `pre-review/` 是排错记录。早期 CPU 默认值标注为 10 有误，最终依据官方 v3.0.0 原文改为 8，旧报告没有被覆盖。

可执行脚本：`run.py --prepare` 冻结新实验目录，`run.py --strategy … --split …` 运行；`live.py` 是显式付费探针；`publish.py` 校验后生成本地发布记录。默认目录不可覆盖已有报告。神经实验需要另行配置本地 BGE/MiniLM 资产，权重不随项目提交；当前默认模型重排通过已配置的 DeepSeek API 调用。

本轮是本地验证版本，尚未推送或部署公网。后续部署必须同步前后端代码与这一组结果，并重新核对线上实际策略，不能将本地数字直接标成线上成绩。
