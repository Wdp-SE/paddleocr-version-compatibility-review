# 检索与审查可靠性检查

本轮保留内部研发知识查询、同一应用升级审查的业务范围和 PaddleOCR 固定版本语料。重点是区分检索遗漏、生成遗漏、适用范围错误与实际运行验证，避免把模型返回成功当成任务正确。

## 行为变化

- RAG 按问题要点检查回答覆盖，最多核验四个要点；超出的要点提示拆分。主张有引用不代表问题已答全。检查器返回未知 ID、越界主张或错误版本时不能关闭要点；模型覆盖判断不属于人工准确率认证。
- 生成补查仍最多一次，保留问题、版本和资料范围。补查将候选预算扩到 120、Top-K 至少为 8，并使用完整结构单元，每个来源块最多选取八个窗口。扩大来源数量不能解决同一长文档内部被丢弃的表格行，因此同时调整来源内的证据预算。
- 通用 OCR 的参数建议不能静默切换到端到端分支；明确问识别或检测阶段时，分别检查 `rec_`/`drop_score` 与 `det_` 参数族。该规则是保守的领域约束，不是通用语义验证器，仍可能拒绝合理的复杂说明。
- Agent 可在当前会话保存报告基线，对照文件新增、修改、移除与同规则/同文件的风险变化。缺文件或无法分析时保留未知，不把风险消失解释为修复认证。目的、版本、语料、分析策略变化时拒绝直接对照；旧处置和回归记录不自动沿用。
- 单 Streamlit 进程最多四个执行任务、八个执行或排队任务。同会话相同输入不会重复提交；跨会话不复用结果。排队取消可阻止调用，运行中的网络请求只能等待返回或传输超时。诊断只展示任务 ID、阶段、耗时和安全错误类别，不写入应用原文。

## 同题、同语料的证据预算对照

日期：2026-10-17。题目沿用 `retrieval_upgrade_v2/final/dataset.json` 的 48 道回归题和 12 道已见验证题；没有重新包装成盲测。

| 配置 | 48 道回归题 | 12 道已有验证题 |
| --- | ---: | ---: |
| 普通窗口 BM25，80 候选、Top-K 5、每来源块 4 窗口 | 32/48 | 7/12 |
| 结构窗口补查，120 候选、Top-K 8、每来源块 8 窗口 | 33/48 | 10/12 |

计分是指定版本、模块、来源及原文标注点的完整字面覆盖，不是回答准确率，也不是所有相关文档的 Recall@K。不同正确来源可能不满足指定原文标注。多项预算同时改变，不能把提升单独归因于结构分块；本轮不宣称已重新完成六策略神经检索选型。

## 生成与检查器定位

`run_diagnostics.py` 分开记录原始语料、候选集和最终上下文是否命中标注。可对指定题目提供人工定位的真实原文单元作为 oracle，对照正常证据与 oracle 证据在相同生成、核验流程下的结果。oracle 同时减少干扰和改变上下文长度，不能据此自动断言某一个算法是唯一原因。

检查过程中，`fresh-17` 在正常结构窗口中拒答，提供对应原文后可回答；`fresh-23` 曾生成有引用但适用分支错误的参数建议。这两种情况分别说明上下文不足和引用支持不足以保证答对。参数族约束接入后，真实调用中 `fresh-23` 经补查得到 `drop_score` 与 0.5 的正确字段和值，同时保留被移除主张的提示。`fresh-17` 在后续完整链路复测仍拒答，属于未解决的失败项，不能声称已全部修复。

四个界面 RAG 示例在本轮实际调用中均返回可展示回答；这属于运行验收。仍需逐条核对答案，并扩展由独立人员标注的未见问题。`run_live_checks.py` 保留完整返回和源代码哈希供本地检查，不把原始模型记录自动发布。

## 复现

从仓库根目录执行；需要安装服务依赖。默认诊断不调用外部模型。输出文件已存在时拒绝覆盖。

```powershell
python evaluation/reliability_v1/run_diagnostics.py --output .local-demo-temp/reliability/plain.json --splits regression,validation --no-structure-windows
python evaluation/reliability_v1/run_diagnostics.py --output .local-demo-temp/reliability/repair.json --splits regression,validation --max-windows 8 --candidate-budget 120 --top-k 8
```

仅在数据传输已授权、服务端配置模型后运行生成验收；公开演示不得提交企业私有资料：

```powershell
python evaluation/reliability_v1/run_live_checks.py --base-url http://127.0.0.1:8786 --output .local-demo-temp/reliability/live.json
```

上述初轮的诊断输入与对照基线保存在 Streamlit 会话中。后续已登记 Git 入口增加本地 SQLite 任务与成功查证响应留存，见[提交审查说明](../../docs/registered_application_review.md)；仍不提供跨实例调度或云临时盘永久保存保证。Agent 不执行上传代码、不自动修改或批准升级；实际 OCR、环境和 JSON 契约回归由开发者完成。规则变形与注入注释回归只验证已覆盖的静态边界，不能称为完整提示注入防护。旧六策略成绩保留为历史实验，不因本轮源码变化自动成为新成绩。
