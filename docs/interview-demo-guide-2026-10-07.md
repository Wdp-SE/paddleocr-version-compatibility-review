# 内部研发知识与升级审查：面试演示指南

## 一句话定位

面向内部研发工程师、测试人员和应用负责人，查询版本化研发资料，并审查同一文档处理应用的依赖升级影响。学生 POC 使用 PaddleOCR 官方资料代理内部组件知识，使用原创应用演示“扫描页 OCR → 结果归一化 → 下游 JSON”；不声称有真实企业用户或生产数据。

支持的升级固定为 PaddleOCR v2.9.1 → v3.0.0。上游依赖版本和内部应用版本是两条轴，内部应用版本尚未登记。完整边界见 [business_scope.md](business_scope.md)。

## 5～8 分钟演示顺序

本次本地预览地址：http://127.0.0.1:8524/。它只对当前电脑可用，本次修改尚未发布到公网。

先用两个明确可答问题说明版本与引用，再用升级比较展示部分可答边界，最后展示不能由官方资料确认的内部事实。Agent 默认打开旧结果消费案例，然后切换另外两个案例。模型生成存在波动，可以点击“仅查看检索原文”先展示固定证据；不能把以前一次成功响应说成每次都会成功。

## 本次技术取舍与收益

1. 查询问题、版本、产线范围在检索前约束；查询别名用于候选召回，不能改写证据。代码/API 名称与参数较多，保留 BM25 词法召回、多查询 RRF 排名融合和上下文窗口，不把 RRF 说成向量模型。
2. 按问题的证据角色选材料：参数问题找调用示例，测试问题找断言，升级结果问题保留两版调用行为和字段契约。避免只给部署说明、测试夹具或打印字典。
3. 保留既有 384 字符窗口、40 候选、Top-5；界面可调整 Top-K。默认未配置神经模型，不冒充已完成新向量/重排选型。部分答案的纠正仍只有一次预算，可扩大候选与证据量，最终返回诊断里的实际配置。
4. 逐条绑定真实引用，机械范围检查后再做模型支持检查；检查器也看原问题，防止“事实是真的但没回答问题”。模型核验不是正确率认证。
5. 修改后第二轮答案独立展示，避免拼接两轮同义答案。结果容器、单页对象、打印/序列化表示分别看待，不能仅凭打印字典断言 Python 接口返回字典。
6. Agent 的官方契约义务调用同一 RAG；应用控制流、缺文件和运行回归缺口直接转人工补证，不再反复查询官方资料。最多 3 轮、24 次检索、240 秒查证预算，支持受约束的恢复。
7. 报告突出结论、风险位置、证据和下一步；回答分“直接回答”和“必要说明”，长内联代码改为代码块，详细核验说明折叠。保留必要边界，不显示未经校准的置信度百分比。

跨文件静态返回值总结只覆盖受支持的直线本地函数，最多 200 个函数、6 次传播；装饰器、条件/循环包装、动态加载、无法证明的关系不提升为已支持结果流。它不是完整跨过程静态分析器。

## 可以诚实引用的数字

最终代码重新回归已有 48 条源文件标注题，完整证据覆盖为 **31/48（64.6%）**，原始 BM25 为 **18/48（37.5%）**；分别为开发组 13/24、验证组 10/12、历史留出组 8/12。它们本轮全部已知，不能称新盲测；这里衡量必需事实证据是否齐全，不是答案准确率。还有 17 条不完整，不能称生产达标。

24 个已知静态结构探针中，14 处预期风险位置全部命中，未出现额外标注风险或把未知判兼容。这是开发者标注的受支持规则回归，不是完整业务任务成功率或运行验证。

最终真实 DeepSeek 验证包含四个展示问题和三个补充问题：五次返回答案、一次预期范围拒答、一次模型响应结构不合规被拦截。升级比较是部分支持。保留所有响应，不只保存成功结果。实际返回模型标识为 `deepseek-flash`，请求标识为 `deepseek-v4-flash`，以响应诊断为准。

10 月 7 日自动化回归：服务端 466 passed / 1 skipped，Agent 184 passed，界面 185 passed / 10 skipped。10 月 8 日查询交互修改后的界面全量回归：192 passed / 10 skipped。跳过项不算通过；这次没有重新测量整体检索准确率。具体记录与限制见 [原实验说明](../evaluation/interview_release_v1/README.md)和[本次交互验证](../evaluation/query_experience_v1/README.md)。

## 最有价值的失败案例口述

“最初升级题能检索到结果打印示例，但生成会把打印字典说成接口返回字典。只检查引用 ID 不够。我保留了失败记录，补充接口行为证据，并让生成和核验区分返回容器、单页对象和序列化表示；不足的部分仍明确留缺口，而不是保证完整兼容。”

“另一个缺陷是模型两轮回答拼接导致重复。我改成第二轮回答独立核验、独立展示，失败时保留前一轮已有支持的部分。没有靠修改正确答案或取消引用检查让展示看起来成功。”

“Agent 不会拿官方组件文档证明公司应用的控制流或 JSON 合同。组件升级事实来自官方固定来源，应用位置来自提交代码，业务验收来自原创契约和开发者环境回归；缺哪一类证据，就交回对应负责人。”

## 不要声称已实现

没有真实内部用户、生产数据、企业身份权限和线上收益指标；没有任意仓库兼容审查、完整依赖图、自动修改或升级批准能力。本次未执行用户提交应用，也没有在三种演示变体上重新运行真正 OCR 推理。已有真实版本实验只能代表当时的特定样例，不能自动套用到当前提交应用。

展示阶段优先把上述四题与三案例讲清楚。下一步应由未参与调参的人构造新问题/应用变体，固定版本和事实标签后测检索、生成支持度及风险定位，补最常见失败；不继续增加无关场景或以已知题成绩证明泛化。
