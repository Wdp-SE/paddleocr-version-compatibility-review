# 内部研发知识查询与变更影响审查业务约束

确认日期：2026-10-07。

## 目标使用者和业务对象

面向公司内部维护文档处理应用的研发工程师、测试人员和应用负责人。被维护的内部应用使用 PaddleOCR 作为底层 OCR 依赖，由自己的调用层与适配层转换为统一输出契约，并交给下游消费者。

项目是学生原创 POC，模拟企业内部研发维护任务。公司背景是场景假设，不是已经发生的企业项目经历；原创代码、资料和测试应标记其身份。

## 固定业务主线

内部版本化研发资料 → RAG 日常查询与证据供给 → 发起同一应用的明确变更 → 静态检查应用位置与支持范围内的关系 → Agent 调用 RAG 查证 → 风险、影响候选、缺口和回归要求 → 工程师人工审核 → 在授权开发环境修改并运行回归 → 负责人决定是否升级。

当前 POC 聚焦 PaddleOCR v2.9.1 → v3.0.0 的依赖升级。日后扩展配置、契约或接口变更时，须继续围绕同一内部应用，另行实现规则和验证覆盖，不能仅凭提示词宣称支持。

## 语料、案例与审查问题的一致性

默认主案例固定为扫描页输入 → PaddleOCR 中文 OCR 调用 → 原始结果归一化 → 下游 JSON 输出。维护者查询当前依赖的用法与契约，并在升级时审查调用入口、旧结果读取、适配层及下游消费要求。实际示例必须具有相应调用或消费位置，不以无关业务故事代替应用证据。

PaddleOCR 代理语料对应内部文档处理组件的版本知识，而不是一家公司的所有业务知识。官方文档可支持接口、参数、结果与迁移事实；原创应用的字段要求、消费逻辑和测试验收须来自实际提交的应用资料，不能从官方说明推断公司内部事实。

PPStructure 公共 API 迁移是同一文档处理领域的相关检查分支；当前默认完整应用只展示 OCR 主链。没有具体分支代码和运行记录时，不能说默认应用已经使用该功能或版面、表格迁移已经验证。新增案例必须同时具备真实的组件变化、实际应用使用位置、可检查的影响候选与相应验证要求。

补充资料只为这些任务服务。引入同仓库的训练、导出、部署资料时，须说明与实际应用任务的关系；不把所有模型训练资料默认当成内部应用升级依据，不引入无关项目拼接场景。

## RAG 的资料范围

真实企业中的业务知识源可以包含设计说明、接口与调用说明、运行配置、输出契约、测试规范和升级记录。学生无法获得企业私有资料，因此当前 POC 使用 PaddleOCR 固定版本的真实开源中文文档、必要代码和配置，作为内部研发知识库的代理语料。

这种映射模拟资料在业务中的作用：使用指南对应内部操作与开发指南，接口代码对应组件接口契约，YAML 对应运行配置，迁移说明对应版本升级资料。映射不改变来源身份，不能把 PaddleOCR 官方资料标成企业原创或真实私有资料，也不能声称已经获得实际公司的完整研发档案。

现有原创应用及其输出契约、测试资料用于演示内部消费者如何受升级影响；后续按实际审查缺口补充即可，不要求为了模拟内部背景另造一套资料作为主语料。

资料至少需要区分项目身份、资料类型、来源身份、适用内部应用版本和依赖版本。内部应用版本与 PaddleOCR 发布版本属于不同版本轴；没有内部版本记录时必须如实标记。

人工查询和 Agent 查证共用同一证据服务。查询范围须依据内部项目及适用版本限定；证据不足时说明缺什么资料，不用外部无关内容填补内部事实。

## Agent 的审查边界

审查目标是内部应用的调用、配置、适配逻辑、输出契约、下游消费及相关测试，不是替上游维护 PaddleOCR 或自动判断任意仓库兼容。

已验证的静态发现、关系候选、模型建议、资料缺口和运行验证状态分别保留。对不支持的动态关系和未提交文件显式标记缺口。引用存在或模型核验通过不等于业务判断一定正确。

Agent 不执行提交的代码、不自动修改应用或上游、不批准升级。真实回归在开发者控制的环境完成；原创样例的运行结果不能自动套用到用户应用。

## 产品与演示边界

公网免登录页面用于面试官体验公开或原创模拟资料，产品目标用户仍是内部研发人员。真实企业资料不能因此进入公开演示。没有权限管理和可靠持久审计时，不宣称具有企业账号隔离或实名审批能力。

不增加与当前内部应用无关的领域语料，不将本项目变成通用开源文档搜索、外部客户支持或广泛自主代码修改平台。

## 当前 POC 的资料映射与验证边界

截至本次检查，活动 RAG 清单主要包含 PaddleOCR 官方中文文档、Python 契约和 YAML 配置；原创内部应用资料位于 `examples/paddleocr_document_app/application/`，应用代码主要通过受限静态文本审查接入。

使用公开资料代理内部知识库是本 POC 的明确设计，不是必须更换语料才能成立的缺陷。它验证版本化检索、证据约束审查和人工确认流程；不验证真实企业资料覆盖、实际用户收益或生产环境权限隔离。不能将公开资料的覆盖率直接解释为企业内部知识覆盖率。

官方资料与原创应用资料必须有不同来源标签。应用文件影响分析继续依靠受限静态工具；仅增加文档索引不能证明获得完整依赖图或端到端业务准确率。

资料和策略变化后须重新验证检索、回答及审查，保留旧实验作为历史记录，不把旧成绩标成新版本效果。
