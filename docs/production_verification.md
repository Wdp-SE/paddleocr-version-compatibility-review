# 内部服务基础验证记录

日期：2026-10-17。范围是本地工作树的内部研发知识与升级审查服务，未推送或部署生产环境。PaddleOCR 资料保持真实来源身份，原创应用仍为扫描页 → OCR → 归一化 → JSON。升级案例固定 v2.9.1 → v3.0.0。

本记录描述首轮验证。当前的部署检查范围和验收条件见 [内部服务部署与验收](../deploy/internal/README.md)。

## 已验证的行为

- 内部 API 验证 JWT 签名/issuer/audience/有效期，使用服务端应用权限；缺配置不匿名启动。JWT 测试使用本地生成的 RSA 密钥，不是企业 IdP 验收。
- 提交与重试共同遵守活动任务容量；重复输入幂等；浏览器读取不改变任务状态。租约过期可接管，旧 Worker 和取消任务不能回写。
- 应用/基线提交、输入哈希、策略、语料与实际执行代码进入任务身份；Worker 本机与 API 不一致时拒绝执行。模型授权基于实际运行提供者，最终拼接提示词再经过出口检查。
- 真实资料索引、API、Agent、独立 Worker 的集成测试跑过三个原创案例：旧式读取定位风险；字段适配不再报告同一风险；缺调用层保留资料缺口。测试身份与 HTTP 传输为适配器，未执行待审代码或调用外部模型。
- CI/人工记录绑定当前提交和报告，错误工作流、提交、输入/报告哈希被拒绝；来源可信与兼容性通过分开，不自动批准升级。
- 内部界面只负责提交、查询、取消和显式重试，终态停止定时轮询。默认演示界面仍保留；企业入口缺身份时明确拒绝匿名操作。
- 索引发布验证原文、固定来源、索引和 gate 身份，比较当前版本后原子切换指针；篡改/错误 gate 被拒绝。SQLite 备份可恢复到新数据库，覆盖已有数据库被拒绝。此项不能替代 PostgreSQL 恢复演练。

## 效果及测试口径

后端完整测试：575 通过、2 跳过；Agent 完整测试：189 通过；原创应用契约测试：10 通过。最后新增 Worker 代码身份拒绝案例后，内部服务专项汇总为 40 通过、1 跳过（真实 PostgreSQL 未配置）。最后一轮界面完整测试为 249 通过、10 跳过。测试套件之间存在重合，不能将这些数字相加冒充独立业务案例数。

RAG 对同一已知 60 题重新做原文/候选/上下文字面事实诊断：默认参数下上下文覆盖为回归集 31/48、验证集 10/12。逐题覆盖与优化前一致；本轮参数定义窗口的针对性测试通过，但没有证明总体检索效果提升。这些数值**不是回答准确率、生成成功率或企业召回率**，本轮没有做外部模型生成式验收。

过往 CPU OCR 运行记录不应自动附到本次新代码或新任务，也不能作为当前应用提交已通过的证明。当前报告只有绑定同一提交、契约、测试及实际环境的受信运行记录，才能说明对应回归确实执行过。

## 独立审查与部署检查

独立只读审查提出并复查了任务重试容量、实际提供者授权、就绪检查、基准提交一致性和 Worker 执行代码身份问题，均已修复并补测试。最后一轮未发现新的明显阻断。

Linux CPython 3.11 amd64 部署锁固定了 74 个轮子及 SHA-256，下载文件哈希校验通过。Compose 配置使用占位的私有路径和镜像 digest 做语法/结构解析，退出码为 0；没有启动正式容器。

## 尚未通过的外部验收

- PostgreSQL：本机 Docker Engine 未就绪，真实并发/租约测试尚未执行；CI 已加入仅允许 disposable `review_test` 数据库的测试。不能用 SQLite 通过替代 PostgreSQL 通过。
- 企业 SSO 与刷新身份代理、私有 TLS 网络、受信 CI 工作流、数据库备份恢复：需要真实部署配置后逐项验收。
- 镜像构建启动、漏洞扫描、负载、故障恢复目标、费用与 token 结算：未实测，不声明 SLA 或生产容量。
- 浏览器验收：自动审批因审批服务额度限制拒绝打开本地预览，本轮未完成真实浏览器操作；Streamlit AppTest 已覆盖身份缺失、单次提交与终态停止轮询。

这轮交付是可继续部署验收的内部服务基础，不能据此宣称企业生产可用性已经证明。
