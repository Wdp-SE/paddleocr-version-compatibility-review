# 面试封版口径

本版固定业务与演示案例，后续投递使用同一版本。只修复阻断演示的缺陷；新增场景、语料与策略在后续分支开展。本文优先于旧面试材料中的过期数字。

## 90 秒介绍

我做的是面向内部研发、测试与应用负责人的版本知识查询和应用升级影响审查 POC。学生无法获得企业内部资料，所以使用 PaddleOCR 官方中文文档、代码和配置代理内部组件知识，并保留真实来源身份；原创应用模拟扫描页 OCR、结果归一化及下游 JSON 消费。

RAG 按依赖版本提供可追溯证据，Agent 调用同一服务，结合受限静态分析定位旧结果索引与应用关系，输出风险、影响候选、未完成核查和回归要求。已支持的升级是 v2.9.1 → v3.0.0。Agent 不执行提交代码，不自动修改或批准升级；工程师仍须在自己的环境完成回归。

我的重点是版本适用性、证据约束和失败可解释。做过 BM25、结构窗口、真实神经混合检索及重排的同资料对照，采用冻结源码和来源的方式防止旧成绩被误用于新版本。模型检查通过不等于人工确认正确，静态风险也不等于实际推理验证。

## 固定演示顺序

1. RAG：当前版仅识别调用，展示版本限定、参数条件与引用。
2. RAG：目标版结果字段与阈值，展示复合问题和资料缺口。部分回答要明确说出未覆盖要点。
3. RAG：两版旧结果读取迁移，区分调用返回列表、单页结果字段和打印表示。
4. RAG：改用新版接口是否足以证明内部 JSON 兼容，展示官方资料不能证明未提交的内部事实；条件清单也不能变成兼容结论。
5. Agent：默认旧消费应用，定位旧式索引的风险和下游回归要求。
6. Agent：切换字段适配变体，展示静态风险消失后仍需环境与文档回归。
7. Agent：移除调用层，展示证据链不完整时的保守结论。

三种 Agent 输入是同一原创应用的明确演示变体，不是三套企业生产应用。没有运行附件时，报告始终保留 `runtime_verified=false`。

## 新鲜验证与限制

2026-10-09 全量回归：后端 472 passed / 1 skipped；Agent 184 passed；UI 202 passed / 10 skipped。跳过项不算通过，单元测试数不等于业务准确率。旧语料相关集成测试及诊断测试原样归档，配置 API 通用约束仍以合成来源测试，当前 PaddleOCR 不宣称支持通用 YAML 依赖图。

四道 RAG 与三种 Agent 输入各运行两次，完整记录见 `evaluation/interview_release_20261009/`。Agent 三分支结论一致；RAG 复合问题仍有部分支持、缺口及模型波动。HTTP `OK` 只代表请求返回，不能当成全答对。验收中的模型支持度是模型判断，不是独立专家评分。

本地运行时间受机器、并行评测和供应商状态影响，不作为公网 P95 或服务承诺。真实神经模型本地实验与免费公网运行配置须分别说明；缺少模型时明确回退，不能将回退成绩叫混合检索成绩。

检索指标只描述固定题集的证据覆盖，具体数字以当前源码校验通过的对照记录为准。已见过的题集复验只能叫回归，不叫新的盲测。真实旧消费者失败与适配器通过的回归记录只证明对应原始输入、环境及应用版本，不证明任意扫描件或客户应用已兼容。
