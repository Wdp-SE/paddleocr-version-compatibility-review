后续复核修正了打包、认证缓存、CI 结果选择、租约与界面版本状态等遗漏，详情见 [补充复核](production_deep_review.md)。

## 服务边界

Streamlit 保留查询与展示职责。内部 API 认证调用方、检查应用 ACL、创建任务及读取报告。独立 Worker 从持久数据库领取任务，读取登记 Git 对象，调用同一受限静态审查和 RAG 证据服务。客户端只传登记应用与 Git 引用；不提供任意仓库地址、文件系统路径、模型地址或执行命令。

数据库保存不可变任务身份、调用人、输入快照、租约、阶段、结果和审计事件。任务身份包含应用提交、基准提交、登记策略、语料/分析策略及建议设置。重复提交幂等，读取不能更改运行状态。Worker 心跳维持租约，过期任务允许接管，旧租约不能完成、失败或覆盖新结果。取消是持久状态，外部在途请求不承诺即时停止或恰好计费一次。

任务同时绑定实际 RAG、Agent、配置及编排代码，Worker 核对本机执行指纹与 API 身份。基础应用引用先解析为固定提交；基准快照使用同一次解析出的 SHA，避免可变分支移动形成混合证据。

内部模式必须配置受信 OIDC issuer/audience/JWKS、服务端应用 ACL 和持久数据库；缺少配置拒绝启动。JWT 仅接受固定非对称算法及受信配置，不接受客户端指定 issuer/JWKS。公开演示模式继续只使用公开与原创资料，不宣称企业权限。内部前端从受信认证代理接收短期访问令牌；后端始终独立验证，代理必须阻断绕过访问。

应用 ACL 控制读取、发起和审核，Worker 为独立服务主体。模型数据出口按登记应用与部署策略配置，默认禁止；启用需明确提供者、资料等级、上下文/调用预算。禁止将恢复令牌、企业访问令牌或完整资料写入普通日志。Worker 不保存用户 JWT。

## 运行与验收

本地开发可使用 SQLite 验证事务和状态；生产使用 PostgreSQL 与独立 Worker。数据库事务使用显式连接关闭；租约更新和完成使用比较并更新。任务 API、Worker 和模型调用有不同超时与容量预算。真实运行结果由受信 CI 提交，绑定应用提交、依赖、契约、测试与运行身份；记录可信来源不等于测试覆盖充分。匿名记录保持未认证标签。

存活、就绪及模型降级分别表达。基础检索或数据库不可用不能仍报告生产就绪；可选模型故障不阻断静态结果。报告保留范围、缺口、人工事项，纯人工事项不提供无意义自动补查。索引发布验证字节身份和任务回归后原子切换，可回滚；权限收回后不得复用旧授权缓存。

验收包括：旧/新/缺文件案例、推导式与循环等价性、无关列表阴性；检索候选到上下文覆盖；越权和过期 JWT；多 Worker、租约过期、旧 Worker 回写、取消、重复提交；CI 错提交/错工作流；就绪失败、模型超时、容量和备份恢复。运行目标由真实压测确定，不预设已经达到的 SLA。
