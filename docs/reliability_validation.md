# 检索与升级审查的可靠性边界

本页说明内部文档处理应用的版本知识查询和升级审查行为，业务范围仍以 [business_scope.md](business_scope.md) 为准。PaddleOCR 公开资料保留真实来源身份；应用代码和契约属于原创演示数据。

## 检索证据

- 默认使用结构化窗口 BM25；多查询结果通过 RRF 融合。完整 API 标识符和拆分后的标识符部件都参与检索。
- 参数问题优先选取表格中第一列确实定义该参数的行；HTML 和 Markdown 表格均按完整行构建检索单元，保留参数名、说明和默认值的对应关系。源码实现问题不使用这一优先规则。引用参数的调用代码不等于参数定义。
- 批量大小等自然问法按任务词汇匹配定义行，优先于 FAQ 中重复的引用；仍保留相关包使用指南，不能为消除默认值冲突而隐藏另一来源。排序不填入参数值，也不把匹配当成答案证明。
- 结果迁移查询识别“按下标取文字”等口语表达；未指定其他产线时沿用本工作区 OCR 主链范围。明确指定 PPStructure 等产线时保留其范围，不能混用其他产线的同名字段。
- 排除 Markdown 标题、表头和空布局窗口；Python 注释及 YAML 配置不按 Markdown 布局删除。原始语料和引用定位不改写。
- 正常检索候选预算为 80、默认返回 5 个来源，每来源最多 4 个窗口；补查最多一轮，候选预算 120、至少返回 8 个来源、每来源最多 8 个窗口。用户指定的版本、语言和问题保持不变。有效且与当前代码匹配的已发布策略可覆盖默认配置。

检索命中不代表答案正确。证据覆盖、原文支持检查和整题完整性分别记录；历史实验在源代码或语料漂移后失效，不把旧分数用于当前版本。

## 回答与补查

- 把生成器报告的缺口作为待核对数据传给复核器，不能作为新事实或指令。
- 生成器报告缺口而复核器认为答全时，显示“完整性核验意见不一致”，保留有支持的内容和缺口。
- 通用指南的结果窗口未重复类名时，可从同一规范原文块中唯一的 `PaddleOCR(...)` 构造确定 OCR 场景；多个已知产线构造混在同一原文块时，不借此为未标明来源的输出指定产线。此规则只核对适用范围，字段含义仍需原文支持。
- 补查不能丢弃第一轮已覆盖的要点；无覆盖增益或补查失败时保留第一轮。两轮分别记录主张、完整性、缺口与选择原因。
- “尚未评估完整性”不等于“发现证据缺口”，不会仅因此发起额外模型调用。
- 问“我们公司/团队的输出是否已经兼容”属于未提交的应用事实，直接说明边界，不为此反复调用模型；问“需要核查哪些字段或测试”仍可依据组件资料提供条件式清单。
- 文档中同名参数的不同默认值须区分调用场景。扩大检索仍可能漏掉正确参数，或引入其他产线的噪声；当前实现没有承诺任意问法均可完整回答。

## 静态审查与复查

- 跟踪 OCR 调用结果通过变量、已支持的局部调用和保持元素的序列包装传播。支持 `list(result)`、常量切片及简单的保持元素列表推导；同名内建函数被参数遮蔽时不套用内建语义。
- 字典携带、迭代器提取、不透明转换、未知修改函数和异步返回等未证明的传播方式，输出带文件和行号的阻断缺口，不能静默视为无影响。
- 未知函数可能修改结果及其别名，不能继续使用此前的形态推断证明旧式消费风险。已识别的 `rec_texts` / `rec_scores` 字段投影不因此误报为不透明序列转换。
- 复查区分风险仍存在、当前未观察到和无法确认。当前未观察到不代表已经修好，更不代表真实推理或下游 JSON 契约已验证。
- 已知缺失的版本事实先按来源路径和符号定向补查，再考虑模型规划。继续受最多 3 轮、12 个查证项、24 次检索及总时限约束；应用测试义务不能用官方检索关闭。
- `lookup_gaps` 和 `official_lookup` 只反映组件资料查证；待人工处理的应用资料与运行义务保存在 `application_validation_requirements`，阶段状态为 `application_validation: pending`。二者仍在完整查证轨迹中保留，页面分别展示；资料查证完成不代表运行验证完成。

## 回归入口

在各子项目目录运行 `python -m pytest tests -q`。关键定向测试包括：

- 后端：`test_evidence_units.py`、`test_requirement_coverage.py`、`test_answer_resolution.py`、`test_ocr_result_origins.py`。
- Agent：`test_paddleocr_investigation.py`；验证定向补查、预算和恢复边界。
- 页面：`test_reading_layout.py`；验证核验分歧可见且已支持回答仍保留。

这些开发回归和已知反例验证的是指定行为，不代表独立盲测准确率、企业真实使用效果或 OCR 运行环境兼容性。
