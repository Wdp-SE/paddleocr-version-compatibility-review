# LangGraph 统一编排迁移

本轮依据用户明确选择的方案 C，将知识查询、依赖升级审查和同版本配置审查的执行编排迁入 LangGraph。领域检索、静态分析、来源验证、输出契约与人工处置规则继续由原有服务负责；这不是重新定义业务或增加自动代码修改权限。

## 架构与入口

- `versioned-rag-service/src/rag_graph.py`：查询子图含范围检查、检索、上下文组织、生成、主张核验和回答；外层图按条件执行一次证据补查，并选择完整且有支持的回答。`public_api.py` 保留路由与兼容调用接口，原顺序式编排已移除。
- `change-review-agent/app/review_graph.py`：共享类型化图状态和执行构建器；升级及配置各自实现输入、静态检查、证据核验、官方查证和报告节点；升级按条件进入模型建议，配置按证据与依赖状态决定是否查证。
- `versioned-rag-service/src/graph_runtime.py`：内部 Worker 注入的 TaskStore 检查点适配器，保存 JSON 数据和待提交节点写入；网关、请求、令牌、回调和函数不进入图状态。
- `internal_worker.py`：继续负责认证、当前构建核对、任务租约、心跳和取消。图状态写入/恢复/节点事件均校验当前领取身份，过期 Worker 不可回写。
- 页面只在折叠的“执行步骤”里读取 `graph_execution`；完成节点不等于 OCR 运行通过或批准发布。

## 恢复与数据边界

内部数据库 schema 从 1 升为 2，增加 `review_graph_state`。部署前停止领取新任务、备份，在管理环境执行 `python -m src.internal_operations migrate`。运行进程只验证就绪，不能边提供服务边自动迁移。现有案例/报告数据不删除；生产 PostgreSQL 迁移与恢复仍需在实际部署环境验收。

检查点绑定任务、主体、应用、请求、构建、图版本和初始输入。只保留最新检查点与 pending writes，单条不超过 5,000,000 字节，拒绝非 JSON/NaN；这是敏感任务数据，应沿用数据库访问与备份策略，不放普通日志。

Worker 崩溃后可以继续已持久化的安全节点。模型相关节点在执行中崩溃、无法判断调用是否完成时返回 `GRAPH_REPLAY_UNSAFE`，不自动重复可能计费的调用。相同请求仍命中相同任务，单纯重试不会解除该保护；可在核对后改变请求（例如关闭模型建议）发起新身份。没有承诺模型恰好调用或计费一次。

普通 RAG HTTP 查询是请求内图执行，未实现跨请求持久恢复；客户端取消后阻止后续节点，但无法强制终止已进入线程的同步供应商调用。公开演示与内部持久任务的恢复能力分别说明。

三条流程禁用隐式 LangSmith 导出，继承的追踪环境变量不能自动将代码、问题或证据发送给新服务。以后启用外部遥测须单独设计数据出口授权。

## 依赖与本地环境

固定 `langgraph==1.1.3`、`langchain-core==1.4.0`、`langgraph-checkpoint==4.0.1`，同步服务、Agent、UI 和内部部署依赖；Linux CPython 3.11 轮子已重新解析并生成哈希锁文件。锁文件生成不等于容器运行或安全扫描已经完成。

本地使用 `.venv-maintenance` 干净环境，避免历史 LangChain 0.3 扩展包与新核心版本冲突；启动脚本优先使用该环境。生产安装采用部署锁文件；FAISS 属于已有扩展测试依赖，不因本轮图编排成为生产基础要求。
