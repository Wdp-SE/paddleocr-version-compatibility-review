# RAG 与升级审查报告阅读调整

本次只调整展示层，保留内部研发知识查询与应用升级审查的固定业务范围。

- 审查报告先显示静态结论、已定位风险、应用位置和下一步核查动作。
- 未发现调用形式变化的发现默认折叠，仍明确要求实际运行回归，不解释为兼容通过。
- 代码与解释、双版本依据、完整验证清单、影响路径、模型建议按需展开。
- 同一发现内的引用，仅在版本、文件路径、URL、提交、文件哈希和行号全部相同且齐全时合并；不同位置或版本仍保留。下载的报告和审核记录不修改。
- 未完成查证按原因聚合显示适用版本，逐项编号与义务保留在查证轨迹中。
- RAG 回答按要点编号，中文长段按句子边界分段，保留各要点引用编号；不在代码内部断句，不通过再次生成改写事实。
- 检索卡片显示最多 180 字符的正文摘录（另加省略号），优先展示含问题字段名的已核验片段，明确标记为节选；省略 HTML 表格排版标签。完整已核验片段和行号在展开区保留。预览 HTML 转义，配图继续使用既有缺口提示。此处只是展示选段，不改变检索排序、证据编号或引用核验。

验证包含 Streamlit AppTest 页面回归、段落与代码保真、来源去重边界、完整原文保留和预览转义。自动化页面检查不能替代检索与生成效果评测。本次展示层调整不重新标记任何旧效果指标为当前成绩。
